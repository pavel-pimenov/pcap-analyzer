## [0.3.0] — 2026-08-25

Серии из браузера, сравнение карт опроса, эталоны и аномалии.

### Добавлено
- **overlap** — сравнение карт опроса двух дампов Modbus: покрытие на
  уровне регистров с частотами, нагрузка на каждый PLC с перекосом,
  каноническая карта (слияние в блоки ≤125) и вердикт с путями
  оптимизации (hot-standby / агрегатор / укрупнение окон).
- **baseline / diff --baseline** — эталонный снимок метрик и правил
  серии в JSON; любой новый дамп сравнивается с ним без хранения
  серии «до».
- Тренды: авто-детект аномалий по MAD (красные маркеры + секция
  «Аномалии в рядах», порог `Config.trend_anomaly_k`).
- Веб-GUI: **серии и дифф из браузера** (выбор файлов «в серию»,
  кнопки «Сравнить» у серий), токен доступа (`serve --token`),
  PDF для отчётов групп.
- Блок «Вывод» в шапке обычных отчётов: счётчики по важности и топ-3
  заголовков.
- `--tz ЧАСЫ` — зона показа времени в любых отчётах.
- Параллельная обработка серий: `--jobs N` у trend/diff/baseline
  (10 файлов s7comm: 69 c → 31 c при N=4).
- Modbus: таблица «Кто и какими запросами вызывает исключения»
  (клиент, диапазон регистров из запроса) + виновники в evidence.
- Fuzz-тесты парсеров недоверенных данных (S7-payload, multipart,
  агрегированные поля tshark).

### Исправлено
- Healthcheck compose работает при включённом токене (бьёт в «/»).
- Лимит размера загрузки проверяется и на финальном чанке multipart.

## [0.2.0] — 2026-08-24

Большой функциональный релиз: три ветки анализа, серийные режимы,
разбор проблем до конкретных тегов и узлов.

### Добавлено
- Ветка **services** — TCP/UDP-сервисы без дизассемблера: сервисы по
  портам, периодика и регулярность циклов (CV), сердцебиения,
  ретрансляции, «молчащие»/односторонние потоки, служебный шум;
  разбор ARP-шторма по MAC-виновникам и целям запросов.
- **Тренды** (`analyzer trend "маска"`): динамика метрик (RTT, ошибки,
  SYN, ARP…) и матрица «правило × файл» по серии дампов.
- **Дифф** (`analyzer diff до после`): сравнение двух серий — ΔKPI с
  оценкой «лучше/хуже» и статусы правил «исчез / появился / в обоих».
- S7comm: ошибки доступа к переменным до конкретных тегов (клиент, PLC,
  DB@адрес), статичные переменные через трекинг значений из tcp.payload,
  глубина конвейера Job, анализ записей Write Var (кто/что пишет,
  конфликты писателей, константная запись), «молчащие» цели :102.
- Modbus/S7: колонки «RST от сервера/клиента» независимо от того, кто
  закрыл соединение первым.
- Конфигурация порогов из TOML (`--config`), упаковка `pyproject.toml`
  с точкой входа `pcap-analyzer`.
- Кнопка «CSV» у таблиц отчёта (офлайн, BOM + разделитель «;»).
- CI (GitHub Actions) на синтетических дампа; генератор тестовых
  pcap-файлов (tests/pcapgen.py).

### Исправлено
- Ограничение выборок RTT/интервалов заработало (Reservoir, алгоритм R)
  — память больше не растёт безгранично на больших захватах.
- Дедлок при завале stderr tshark; гонка drain-потока при закрытии.
- «Короткие соединения» считаются по всем потокам, а не по топу самых
  долгих.
- Сопоставление Job/Ack_Data: лимит очереди на pduref и санитарный
  потолок RTT — переиспользование pduref больше не раздувает перцентили.
- Экранирование problem/advice рекомендаций в HTML.
- CLI печатает понятную ошибку вместо трейсбека при недоступном tshark.

### Изменено
- Общие утилиты веток собраны в branches/base.py; единый формат дат.
- Магические числа перенесены в Config; пороги можно переопределять
  TOML-файлом.
- Прогресс анализа передаёт структурный процент (pct) вместо парсинга
  строк.
- Веб-GUI: стриминг файлов, HTTP/1.1 keep-alive, nosniff, устойчивый
  разбор Content-Length, чистка обрывков загрузок.
