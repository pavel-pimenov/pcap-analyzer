# pcap-analyzer

Инструмент анализа сетевых дампов (pcap/pcapng) с формированием отчёта в
форматах **HTML** (автономный файл) и **PDF**. Разбор пакетов выполняется
утилитой **tshark** (CLI Wireshark), оркестрация и расчёт метрик — на Python 3.14.
Проект поставляется в Docker, включает **веб-интерфейс** для загрузки дампов
и просмотра отчётов.

Первая ветка анализа — **Modbus/TCP**: метрики работы клиентов и серверов,
частота подключений, состав команд, карта регистров, время отклика,
исключения и автоматические рекомендации по оптимизации опроса.

## Возможности (ветка `modbus`)

| Блок отчёта | Что показывает |
|---|---|
| Ключевые показатели | длительность захвата, объём трафика, доля PDU Modbus, клиенты/серверы, соединения, запросы/ответы, таймауты, медиана отклика |
| Активность во времени | график запросов и исключений по минутам; пиковые интервалы |
| Клиенты и серверы | пары «клиент → сервер»: запросы, ответы, исключения, таймауты, p50/p95 отклика, основные функции |
| Соединения TCP | SYN-подключения к порту 502, их частота, длительность потоков, короткие соединения |
| Функциональные коды | гистограмма FC1–FC16: какие команды выполняют клиенты |
| Карта регистров | какие диапазоны читают/пишут, топ диапазонов, число клиентов на диапазон, визуальная карта покрытия, «статичные» регистры |
| Время отклика | min/p50/p90/p95/max по каждому серверу |
| Исключения и ошибки | коды исключений Modbus с расшифровкой, RST/FIN, запросы без ответа |
| Рекомендации | автоматические советы по оптимизации с приоритетами «Критично / Важно / Совет» |

Каждая секция отчёта содержит готовые **команды tshark**, которыми можно
воспроизвести выборки из файла — раскрывающийся блок «Показать команды tshark».

* **HTML** — один автономный файл без внешних ресурсов (стили и графики инлайном).
* **PDF** — тот же контент через печатную таблицу стилей: страница A4, нумерация
  страниц; конвертация выполняется [WeasyPrint] — единственной внешней
  зависимостью проекта (`requirements.txt`).

[WeasyPrint]: https://doc.courtbouillon.org/weasyprint/

### Правила рекомендаций (`analyzer/config.py`)

* объединение мелких чтений в пакетные запросы (до 125 регистров);
* группировка одиночных записей FC6 → FC16;
* частые переподключения к порту 502 (по частоте или повторным подключениям
  одной пары клиент→сервер) → держать постоянное keep-alive-соединение;
* медленные серверы (p95 > 100 мс);
* регулярные исключения Modbus и запросы без ответа;
* интервал опроса ≤ 2×RTT → давление на сервер;
* один диапазон читают несколько клиентов → кэш/агрегатор;
* статичные регистры → вынести в медленный цикл опроса.

Пороги настраиваются в `analyzer/config.py`.

### Ветка services — TCP/UDP-сервисы без привязки к протоколу

Для проприетарной телеметрии, которую Wireshark не разбирает: сервисы
определяются по порту-серверу; отчёт показывает объёмы в обе стороны,
медианные интервалы запросов и регулярность циклов (CV), сердцебиения,
ретрансляции TCP, «молчащие» и односторонние потоки, служебный шум
(ARP/STP/LLDP/NTP/DHCP). Рекомендации: недоступные узлы, односторонний
обмен, потери кадров, переподключения, ARP-шторм.

### Ветка s7comm — Siemens S7 Communication (:102)

Анализ обмена SCADA/HMI с PLC Siemens: клиенты и PLC, функции протокола
(Read Var / Write Var / Setup communication), области памяти (DB, M, I, Q…),
времена отклика по сопоставлению Job/Ack_Data (по `s7comm.header.pduref`),
коды ошибок элементов данных. Рекомендации: медленный отклик PLC,
ошибки доступа к переменным (устаревшие теги), частые переподключения
(лимит одновременных соединений у PLC ограничен), одиночные чтения
вместо групповых.

## Быстрый старт

### Вариант 1 — веб-интерфейс через docker compose (по умолчанию)

```bash
docker compose up --build          # затем открыть http://localhost:8000
```

В браузере: слева — загрузка pcap-файлов и список файлов (включая образцы из
`./pcap-sample`, их удалять нельзя), справа — просмотр отчёта и кнопки
экспорта **HTML** / **PDF**. Загруженный файл анализируется автоматически,
статус виден в списке.

Загрузки и отчёты хранятся в docker-томе `webdata`.

### Вариант 2 — разовый анализ из командной строки (профиль batch)

```bash
docker compose run --rm analyzer analyze \
    /data/<файл>.pcap -o /output/report

# сразу HTML и PDF:
docker compose run --rm analyzer analyze \
    /data/<файл>.pcap -o /output/report -f both

docker compose run --rm analyzer branches        # список веток анализа
```

Файлы берутся из `./pcap-sample` (монтируется как `/data`), отчёты попадают
в `./output`.

### Вариант 3 — docker run

```bash
docker build -t pcap-analyzer .
mkdir -p output
docker run --rm \
  -v "$(pwd)/pcap-sample:/data:ro" \
  -v "$(pwd)/output:/output" \
  pcap-analyzer analyze /data/<файл>.pcap -o /output/report.html -f both
```

### Вариант 4 — локально (нужны tshark и weasyprint)

```bash
pip install -r requirements.txt   # + системные библиотеки Pango (см. Dockerfile)
python3 -m analyzer analyze pcap-sample/<файл>.pcap -o report.html -f both
```

Путь к tshark: флаг `--tshark-bin`, переменная окружения `TSHARK_BIN` или `PATH`.
Для PDF нужны библиотеки Pango/GDK-Pixbuf и шрифты с кириллицей
(в Debian/Ubuntu: `apt install libpango-1.0-0 libpangocairo-1.0-0 libgdk-pixbuf-2.0-0 fonts-dejavu-core`).

## CLI

```
python -m analyzer analyze <pcap> [-o OUT] [-f html|pdf|both] [-b BRANCH] [--tshark-bin PATH]
python -m analyzer serve [--host H] [--port P] [--data-dir D] [--samples-dir S]
python -m analyzer trend "pcap-sample/plc_cgn_*.pcap" -b s7comm \
    -o trend.html --jobs 4
python -m analyzer diff "dump/before_*.pcap" "dump/after_*.pcap" -b modbus -o diff.html
python -m analyzer overlap dump/serverA.pcap dump/serverB.pcap -o overlap.html
python -m analyzer baseline "dump/good_*.pcap" -b modbus -o baseline.json
python -m analyzer diff "dump/new_*.pcap" --baseline baseline.json -b modbus -o vs_baseline.html
python -m analyzer branches
python -m analyzer --version
```

| `trend` | тренды по серии дампов: динамика метрик (RTT, ошибки, SYN, ARP) и матрица сработавших правил по файлам; маска в кавычках |

| Аргумент | Описание |
|---|---|
| `analyze` | разобрать pcap-файл и собрать отчёт |
| `-o, --output` | путь к итоговому файлу; расширение подставляется по формату |
| `-f, --format` | `html` (по умолчанию), `pdf` или `both` |
| `-b, --branch` | ветка анализа (по умолчанию `modbus`) |
| `--tshark-bin` | путь к бинарнику tshark |
| `--config` | TOML-файл с порогами правил (ключи как в `analyzer/config.py`, секции — просто группировка) |
| `--tz ЧАСЫ` | зона показа времени в отчёте от UTC (например `3` или `-5.5`); по умолчанию — локальная машина |
| `serve --token СЛОВО` | закрыть веб-интерфейс токеном: все запросы, кроме самой страницы, требуют `?token=…` или заголовок `X-Auth-Token`; страница запоминает токен в localStorage |
| `serve` | веб-интерфейс (по умолчанию `127.0.0.1:8000`) |
| `branches` | показать доступные ветки и их описание |

Пример локального запуска веб-интерфейса:

```bash
python3 -m analyzer serve --port 8000 --samples-dir pcap-sample
```

## Как это работает

1. **Проход 1** — общий обзор всех пакетов: время начала/конца, объём,
   SYN/RST/FIN на порту 502, длительности TCP-потоков, активность узлов.
2. **Проход 2** — только пакеты `mbtcp`: запросы и ответы сопоставляются по
   номеру кадра (`modbus.request_frame`), при нестандартных портах направление
   определяется по ссылке на запрос; накапливаются счётчики функций, регистров,
   целей опроса, времён отклика, значений регистров, исключений.
3. По агрегатам применяются правила рекомендаций и собирается HTML-отчёт
   (один файл, инлайновые CSS и SVG). Для PDF тот же документ рендерится
   WeasyPrint с печатной таблицей стилей (@page A4, нумерация, запрет разрывов).

Ограничения первой версии: анализируется классический Modbus/TCP (порт 502
или произвольные порты с корректным дизассемблированием); запросы до начала
захвата остаются без пары и учитываются как «ответы-сироты».

## Добавление новой ветки анализа

1. Создайте модуль `analyzer/branches/<имя>.py` с классом-наследником
   `BaseBranch` (метод `analyze(...)` возвращает `BranchResult`).
2. Зарегистрируйте его в словаре `BRANCHES` файла `analyzer/branches/__init__.py`
   — он появится в CLI (`-b имя`) и в выпадающем списке веб-интерфейса.
3. Для рендера используйте хелперы `analyzer/report/components.py` —
   тогда отчёт останется единым автономным HTML и корректно ляжет в PDF.

## Проверка выборок вручную (примеры)

```bash
# кто опрашивает серверы и как часто
tshark -r <файл>.pcap -Y "mbtcp && tcp.dstport==502" \
  -T fields -e ip.src -e ip.dst | sort | uniq -c | sort -rn

# распределение функций
tshark -r <файл>.pcap -Y "mbtcp" \
  -T fields -e modbus.func_code | sort | uniq -c | sort -rn

# времена отклика серверов
tshark -r <файл>.pcap -Y "mbtcp && tcp.srcport==502" \
  -T fields -e ip.src -e modbus.response_time
```

Полный набор команд для каждой выборки — внутри отчёта.
